SummaPass · Bandung Build Challenge 2026 · Summarecon Mall Bandung

One web app for visitors, counter staff and mall admins, one Go API, and one database

Visitors book an arrival slot on their phone and get a short code. Staff redeem that code at the counter, and the TV board shows the queue and the expected wait. Every screen is the same React build behind nginx, every API request goes to one Go process, and every ticket and event lives in PostgreSQL.

The SummaPass API
Go 1.27 · net/http · :8080
  • 17 routes in three groups: public, operational, analytics
  • Booking and cancelling are capped at 30 per 10 min per IP, logins at 10

Where data rests
PostgreSQL 17, the one book
users · events · tickets
  • The last place in a slot is guarded by SELECT … FOR UPDATE on the event row, so two people can't both take it
  • SQL queries, Go code generated by sqlc
  • UUID keys everywhere
  • Seeded with example events and two demo accounts
  1. 1A visitor picks an arrival slot. The phone sends POST /public/v1/tickets.
  2. 2nginx passes the API paths to the Go process. Every other path gets the React build.
  3. 3Booking checks the name (3 to 60 characters) and that the slot exists.
  4. 4One transaction locks the event row, checks the slot quota and saves the ticket. A clashing code is retried, up to 5 times.
  5. 5The phone keeps only the code (and its event ID) and shows it with a QR. Details are fetched again each time.
  6. 6At the counter, staff enter the code, match the KTP and redeem. The ticket is marked early, on time or late, and the 15 minutes before a slot count as on time.
  7. 7The board refreshes every 10 s and shows the wait from the queue count that staff keep up to date.
